# ポータル依頼書: TaneBako 閲覧ページ（`/tanebako`）とメモ・回答欄

- 依頼元: tanebako セッション（オーナー承認済み 2026-11-23）
- 依頼先: info-portal セッション（`/data/apps/portal` の担当）
- 目的: オーナーが iPhone から、TaneBako のMarkdownを読みやすい形で見られるようにする。見ながらメモと質問票への回答を残せるようにする。
- 守る規約（`/data/apps/portal/README.md` に従う）: tailnet のみ（`tailscale funnel` は使わない）／`app.py` は標準ライブラリ＋`.venv` の `markdown` のみ／編集後は `systemctl --user restart portal.service`／ポータルのローカル git に commit／README に追記／秘密情報は扱わない／時刻は JST 明示。

## 1. 閲覧（読み取り専用）
- URL: `/tanebako`（トップ）。ナビに「TaneBako」を追加。
- トップ: `/data/tanebako` の `00_フォルダの見方.md` の内容と、番号つきフォルダ（`01_運営`〜`08_数字`）の一覧。タップでフォルダ内のファイル一覧、さらにタップでファイル表示。
- `05_公開物` は `1_下書き / 2_審査中 / 3_承認済み / 4_公開済み` の順に並べ、フォルダごとに件数を表示する。
- ファイル表示: Markdown を HTML にする（表、見出し、チェックリスト、コードブロック）。スマホ幅（375px 前後）で横スクロールが出ないこと（表は表だけ横スクロール可）。ファイル名・日付・更新日時（JST）をヘッダーに出す。
- コードブロックに「コピー」ボタン（ワンタップで中身をクリップボードへ）。X・note に貼る本文のため。
- 対象: `/data/tanebako/00_フォルダの見方.md`、`CLAUDE.md`、`01_`〜`08_` の下の `.md`・`.csv`（CSV は表で表示）。
- 除外・安全:
  - 許可リスト方式。上記以外（`.git`、`.claude`、隠しファイル、その他）は 404。
  - パスは `realpath` で解決し、`/data/tanebako` の外を指すもの（`..`、シンボリックリンク）は拒否。
  - 1ファイルの表示上限は 2MB。
- 書き込みは、下の2章のメモ保存だけ。元のファイルは一切変更しない。

## 2. メモと回答（`01_運営/メモ/` にだけ書く）
### 2-1. ページごとのメモ欄
- 各ファイル表示の下部に、メモ入力欄（複数行）と「保存」ボタン。iPhone のキーボードの音声入力で使えるよう、普通の `<textarea>`。

### 2-2. 引用してメモ
- 本文の文章を選択すると「メモする」ボタンが出る（`selectionchange` で位置は画面下に固定表示でよい）。
- 押すと、選んだ文章を引用としてメモ欄に入れ、欄までスクロールする。

### 2-3. 質問票の回答欄
- 本文中の表で、1列目が `Q` ＋数字（例: `Q5`、`Q15`）の行を「質問」として検出する。
- 質問の行ごとに回答 UI を出す: ボタン `OK` / `直す` / `あとで` ＋自由記入欄＋「保存」。
- 質問の本文に `【選択肢: A / B / C】` と書かれていたら、その選択肢をボタンにする（`OK` / `直す` / `あとで` の代わり）。将来のアンケートはこの書式で出す。
- 保存済みの回答は、その質問の行に「回答済み（日時・選んだもの）」と表示し、上書き保存を可能にする（履歴は残す）。

### 2-4. 保存する形式（1件 = 1ファイル）
- 場所: `/data/tanebako/01_運営/メモ/`（無ければ作る）。ここ以外には書かない。
- ファイル名: `YYYY-MM-DD_HHMMSS_<種別>_<対象ファイル名の先頭20字>.md`（JST）。種別は `メモ` または `回答`。
- 内容:

```
---
種別: メモ | 回答
対象: 05_公開物/2_審査中/2026-11-17_枠1_Xポスト初期案12本.md
質問ID: Q5            # 回答のときだけ
選択: 直す             # 回答のときだけ
日時: 2026-11-23T21:30:00+09:00
状態: 未処理
---
> （引用した文章）   # 引用してメモのときだけ

（メモ・回答の本文）
```

- 書き込みは一時ファイルに書いてから `rename`（途中で壊れないように）。権限 `0644`、所有者は glitch。
- `状態` を `処理済み` に変えるのは tanebako セッション（Claude）。ポータルからは変えない。
- 入力の上限: 本文 10,000 字、引用 2,000 字。HTML は必ずエスケープ。YAML の値は引用符で囲んで安全に出す（`---` 注入対策）。

### 2-5. 認証・公開範囲
- アクセスは tailnet のみ（既存どおり `tailscale serve` 経由）。保存（POST）は、既存の添付アップロードと同じく `Tailscale-User-Login` ヘッダーがあるときだけ受け付ける。
- CSRF 対策: `Origin` が自分のホストのときだけ POST を受理。

### 2-6. 一覧
- `/tanebako/memos`: メモと回答の一覧（新しい順）。状態（未処理／処理済み）でフィルタ。未処理の件数を、トップとナビに小さく表示。

## 3. しないこと
- 本文の編集、ファイルの移動、`3_承認済み` への承認ボタン（承認はオーナーだけが VSCode 等で行う。憲章の決まり）。
- ntfy 通知（公開サーバーを通るため、まだ付けない）。
- 外部への公開、Funnel。

## 4. 受け入れ確認（実装後に info-portal セッションで確認）
1. iPhone 幅（375px）で、トップ・フォルダ・ファイル（表が多いもの）が崩れない。例: `05_公開物/2_審査中/2026-11-17_枠1_Xポスト初期案12本.md`。
2. 許可外のパス（`/tanebako/file?path=../../.ssh/…`、`.git/config`、シンボリックリンク）が 404／拒否される。
3. コードブロックのコピーが動く。
4. メモ・引用メモ・回答（ボタンあり／選択肢書式あり）が `01_運営/メモ/` に正しい形式で保存される。HTML や `---` を含む入力で壊れない。
5. 質問票つきファイル（`05_公開物/1_下書き/2026-11-23_枠2_Xポスト初期案.md` の末尾の Q1〜Q15）で回答欄が出る。
6. `portal.service` 再起動後に通常のページ（ホーム・ニュース等）が従来どおり動く。README に追記し、ローカル git に commit。
