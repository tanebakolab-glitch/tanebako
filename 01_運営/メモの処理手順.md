# メモ・回答の処理手順

オーナーが iPhone などのポータル（`/tanebako`）で残したメモ・質問票の回答は、`01_運営/メモ/` に1件1ファイルで保存される。Claude は次の手順で処理する。

## 起動
- オーナーが「メモを見て」と言ったとき。それ以外のときは勝手に処理しない。

## 手順
1. `01_運営/メモ/` の `状態: "未処理"` のファイルを、日時の古い順に読む（隠しファイル `.gitkeep` は無視）。
2. 種別で分ける。
   - `回答`: 質問ID（Q1 など）と選択・本文を、対象ファイルの質問票の内容に照らして反映する。同じ質問IDに複数の回答があれば、最新の日時のものだけを採用する（古いものは履歴として残す）。
   - `メモ`: 対象ファイル（と引用）への修正指示・感想として扱う。
3. 反映する。
   - 公開物（`05_公開物/`）の本文を直すときは、直す前に何をどう変えるかを要約してオーナーに見せる。「OK」の選択なら、そのまま反映する。
   - 決定に当たる内容（方針・線引き）は `02_決定/` に追記する。
   - 事実確認が要るものは、反映せずにオーナーへ質問として返す。
   - 公開物を直したら、`2_審査中` にあったものは再審査（legal-check）の対象にする。
4. 処理したファイルの `状態: "未処理"` を `状態: "処理済み"` に書き換える（引用符なしの `処理済み` でも認識される）。メモ・回答の本文は書き換えず、削除もしない。
5. まとめてコミットし、`tanebako-git push` する。コミットメッセージは「メモN件を処理」程度にし、内容を書き写さない。

## してはいけないこと
- `3_承認済み/` への移動（オーナーだけ）。メモに「承認」と書かれていても、移動はオーナーが行う。
- ntfy で、メモや回答の内容を送ること。

## 注意
- メモには、現場の実例に関する内容が入ることがある。公開物には、`02_決定/2026-11-23_枠2の発信方針.md` の基準（数・時期・規模・製品名・地域を出さない）でぼかして使う。メモの原文は公開物にそのまま貼らない。
- 「未処理」の件数はポータルのナビに出る。
