# X 枠2 初期ポスト案 10本（@tanebako_medit 用）

## 方針
- 対象は枠2のXアカウントだけ。枠1（@tanebako）と同じ内容を流さない。枠1の「AIで一人事業の実録」は出さない。
- 守秘・匿名: 勤務先・現場・同僚・取引先・患者・地域・所属・特定の製品や契約に触れない。実体験は書かない（創作しない）。医療ITの経験を語る内容は、オーナーに事実確認してからでないと書かない。
- 内容は2種類だけ。
  - 【読み解き】公開されている法規制・ガイドライン・公式文書の説明（出典つき）。
  - 【方法論】AIを使った検証のやり方・決めごと。これまでに試した結果は書かない。「これから検証する」と方針だけを書く。
  - 【開示】#1 のみ。
- 一般向けの健康・医療情報は扱わない。ガイドラインの対応方法を指示する形（「こうすべき」）にもしない。個別の判断は原文と所管の案内で確認、と添える。
- 文字数は全角140字以内（どれも約100〜120字）。URLは入れない（X API の URL 付き課金が高いため。research/2026-11-15_X_API料金.md）。出典は下の各案に書き、ポストの末尾には「出典：厚労省」のように発行元だけを入れる案もある（審査で判断）。
- 投稿はオーナーが手で行う。legal-check とオーナー承認が済んでから。
- 10本は仮説の初期サンプル。傾向を見るだけにとどめ、判定は30日分で行う。

## ポスト案

### 1. 自己紹介（12-02）【開示】
```
はじめまして、タネバコ医療ITです。医療従事者・情シス向けに、ガイドラインなど公開文書の読み解きと、AIを使った検証の方法を記録します。下書きはAI（Claude）、確認と公開は人間のオーナー。患者情報や特定の組織・製品は扱いません。
```
- 元にした事実: 憲章1・2・5章／decisions/2026-11-21_枠1の公開方針.md（モデル名の開示）

### 2. 4編構成（12-04）【読み解き】
```
厚労省「医療情報システムの安全管理に関するガイドライン」6.0版（2023年5月策定）は、概説編・経営管理編・企画管理編・システム運用編の4編構成。編ごとに、想定する読者に求められる遵守事項とその考え方が示されている。
```
- 出典: https://www.mhlw.go.jp/stf/shingi/0000516275_00002.html （厚労省の審議会ページ。本文の確認が必要）

### 3. 要約の決めごと（12-07）【方法論】
```
AIにガイドラインを要約させるときの決めごと。①どの編・章の記述か、章番号を必ず併記させる。②要約は鵜呑みにせず、人が原文で確かめる。③確かめられなかった部分は、確かめられなかったと書く。
```
- 元にした事実: 運営の方針（検証の方法論）。実際に試した結果は書いていない。
- 要事実確認: これを「TaneBako枠2の決めごと」としてよいか（表の #3）。

### 4. 2つのガイドラインの読者（12-09）【読み解き】
```
医療情報まわりの公的ガイドラインは、読者で分かれる。医療機関等向けは厚労省のガイドライン、医療情報システム・サービスの提供事業者向けは経産省・総務省のガイドライン。どちらの立場で読むかを先に決めると整理しやすい。
```
- 出典: 厚労省（上記）／経産省 https://www.meti.go.jp/policy/mono_info_service/healthcare/teikyoujigyousyagl.html ／総務省 https://www.soumu.go.jp/menu_news/s-news/01ryutsu06_02000427.html
- 備考: 「整理しやすい」は書き手の見解。

### 5. 6.0版の改定の背景（12-11）【読み解き】
```
6.0版は、近年のサイバー攻撃やクラウドサービス利用の広がりを踏まえた改定。ゼロトラスト思考に沿った対策の考え方や、サイバー攻撃を含む非常時の対応も整理されている。個別の対応は原文で確認を。
```
- 出典: 厚労省の通知・ガイドライン本文（https://www.mhlw.go.jp/stf/shingi/0000516275_00002.html）。内容は検索要約で確認。本文での再確認が必要。

### 6. 検証記事の書き方（12-14）【方法論】
```
検証の記録の書き方を決めた。何を、どんな条件で試したか。何が確かめられ、何が確かめられなかったか。製品名や組織は出さず、一般化して書く。AIの出力そのものではなく、人が確かめた結果だけを載せる。
```
- 元にした事実: 憲章2章（匿名・一般化）・5章
- 要事実確認: 方針としてオーナーが了承しているか（表の #3）。

### 7. 2省ガイドライン 第2.0版（12-16）【読み解き】
```
経産省・総務省の「医療情報を取り扱う情報システム・サービスの提供事業者における安全管理ガイドライン」は、2025年3月28日に第2.0版が公表された。医療機関等と事業者との間の取決めの重要性などを踏まえた改定とされている。
```
- 出典: https://www.soumu.go.jp/menu_news/s-news/01ryutsu06_02000427.html （令和7年3月28日の報道発表）
- 備考: 最新版が第2.0版のままか、投稿日に公式ページで確認。

### 8. 入力の線引き（12-18）【方法論】
```
AIに入力するのは、公開されている文書と、架空のダミーデータだけ。患者情報や、勤務先・取引先がわかる情報は入れない。医療ITの検証をAIでやるときの、いちばん最初の線引き。
```
- 元にした事実: 憲章2章（患者情報・勤務先の情報は扱わない）・8章

### 9. オンライン資格確認（12-21）【読み解き】
```
6.0版では、オンライン資格確認の導入に必要なネットワーク機器等の安全管理措置も整理された。個別の対応は、最新の原文と所管の案内で確認してほしい。ここは読み解きであって、対応の指示ではない。
```
- 出典: 厚労省（上記）。本文の該当箇所の確認が必要。

### 10. これから検証すること（12-23）【方法論】
```
これから検証すること。公開文書の要約をAIに頼み、原文と突き合わせて、食い違いがどれだけあるかを数える。条件と、確かめられたことだけをnoteに書く予定。結果が出たら、ここでも報告する。
```
- 要事実確認: 検証を実施する予定か、note に書く予定か、時期。決まっていなければ「予定」の表現ごと外す（表の #4）。
